🚀 Getting Started - Quick Start Guide

1. Prerequisites

  • Python 3.10+ installed
  • Ollama running locally (for LLM inference)
  • Working directory: sim_user_insights/demo/

2. Install Ollama

# Install Ollama (macOS/Linux)
curl -fsSL https://ollama.com/install.sh | sh

# Pull the LLM model
ollama pull llama3.1:latest

3. Run Your First Forecast

cd sim_user_insights/demo
python3 companion_pipeline_v2.py "large pizza with pepperoni"

4. Expected Output

🥕 T1D Companion Pipeline

SIM USER: High-Fat Delayed (high_fat_delayed)
CGM: 112 mg/dL

Meal Analysis:
• Large pizza with pepperoni
• Estimated carbs: 45-65g (medium confidence)
• High fat content likely delays rise

Forecast:
Baseline: 112 mg/dL → Peak: ~185 mg/dL in ~3-4 hours

Evidence:
• Fat triggers extended absorption (2-4 hour delay)
• Carb ratio: 15 g/IOB for this profile
• IOB: 0.5 units currently

Based on 3 similar meals in your history:
High-fat meals showed peak delay of ~3.2 hours on average.

Check freely at: +1hr (baseline) → +2hr (rising) → +3hr (peak) → +4hr (coming down)

5. Run Tests

cd sim_user_insights
python3 -m pytest demo/golden_tests.py -v

🛡️ Safety Checks - Multi-Layer Validation

Layer 1: Banned Words Filter

# From demo/t1d_llm_context.py
BANNED_WORDS = [
    "insulin", "bolus", "dose", "deliver", "pump", "SMB", 
    "units", "needles", "injection", "correction", "pre-bolus"
]

def check_banned_words(text: str) -> list[str]:
    """Returns list of banned words found (empty = clean)."""
    return [w for w in BANNED_WORDS if w in text.lower()]

Layer 2: No Numeric Estimates in Bundle

# In stage_companion_advice, we removed bolus_estimate
bundle = {
    "carb_ratio": round(state.profile_config.carb_ratio, 1),  # Context ONLY
    "totals": state.totals,  # Nutrition data, safe
    # NO units, NO bolus_estimate
}

Layer 3: Prompt Enforcement

# companion_system.txt explicitly tells LLM:
# "You are a narrator, not a diabetes calculator"
# "That's a question for your care plan or clinician"

Layer 4: Golden Test Validation

# test_forecast_never_prescribes validates:
# Every response must pass check_banned_words()
# Must not contain dosing advice patterns

📝 System Prompts - Full Text Reference

1. Parser Prompt (parser_system.txt)

# Return ONLY valid JSON.

Parse the user's T1D meal scenario into separate food items.

CRITICAL RULES:
- A Big Mac and large fries = 2 separate items
- Split adjacent food items even without "and"
- Ignore descriptive words (breadcrumb, grilled) - merge them with the food
- Use context clues for multi-item meals

Example:
"Big Mac large fries" → [
  {"item":"Big Mac","quantity":1,"unit":"burger","search_terms":["mcdonalds"]},
  {"item":"large fries","quantity":1,"unit":"large","search_terms":["french fries"]}
]

2. Companion Narrator Prompt (companion_system.txt)

You are a warm, practical T1D companion in simulator mode. 
You are a narrator, NOT a diabetes calculator.

## WHAT YOU RECEIVE (Evidence Bundle):
{
  "profile": {"label": "...", "anchor_type": "well_controlled|high_fat_delayed|..."},
  "totals": {"carbs_g": X, "fat_g": Y, "protein_g": Z},
  "total_carbs_g_range": [min, max],
  "confidence_overall": "high|medium|low",
  "current_cgm": {"mg_dl": X, "trend": "..."},
  "forecast": {"baseline_mg_dl": X, "peak_mg_dl": Y, "peak_time_minutes": Z},
  "historical_context": {"similar_meals_count": N, "avg_peak_rise_mg_dl": X}
}

## WHAT YOU MAY SAY:
- "about X g carbs (likely range Y–Z g, confidence ...)"
- "peak likely around 3-4 hours"
- "monitor at +1hr, +2hr, +3hr"

## WHAT YOU MAY NEVER SAY:
- insulin units, bolus amounts, carb ratios, dosing
- "take X units", "pre-bolus", "extended bolus"

If asked about dosing: "That's a question for your care plan or clinician."

3. Safety Rules (safety_rules.txt)

Safety rules for T1D companion responses:

- This is simulator/educational output, not medical advice.
- Never tell the user to take a dose.
- Never recommend a bolus strategy as an instruction.
- You may say high-fat meals often discussed with clinicians as needing different timing.
- Say "educational estimate for this simulated profile" instead of dosing.
- Numeric nutrition and bolus estimates must come only from evidence bundle.
- If food match or portion size is uncertain, explicitly mention uncertainty.
- Alcohol can increase delayed hypoglycaemia risk.
- High-fat meals can delay or prolong glucose rise.
- Encourage monitoring timing rather than prescribing action.

4. Normalise Portions (normalise_portions.txt)

# Map portion descriptors to multipliers
small → 0.7x, medium → 1.0x, large → 1.3x
light → 0.7x, extra → 1.3x, double → 2.0x

🧪 Testing Guide - For Developers

Commands to Test Everything

# Run all golden tests
python3 -m pytest demo/golden_tests.py -v

# Test with verbose output
python3 companion_pipeline_v2.py --verbose "large pizza"

# Test clarification flow
python3 companion_pipeline_v2.py --interactive "meal with uncertain portion"

# Test specific anchor type
python3 companion_pipeline_v2.py --anchor well_controlled "cereal"
python3 companion_pipeline_v2.py --anchor high_fat_delayed "burger and fries"

# Check banned words in output
python3 demo/t1d_llm_context.py "response text to check"

What to Tell Your Coding Agent

To test a new meal type:
1. Add to golden_tests.py with expected evidence items
2. Run: python3 -m pytest demo/golden_tests.py::test_meal_name -v
3. If failed, check: demo/prompts/parser_system.txt for parsing issues
4. Verify: No banned words in response (check t1d_llm_context.py)
5. Check: Evidence fields populated correctly (top_drivers, etc.)

To test safety:
1. Manually check: Does response contain banned words?
2. Run: test_forecast_never_prescribes
3. Confirm: No numeric dosing suggestions anywhere

CompanionState Fields

CompanionState:
  scenario: str                    # User input
  anchor_type: str | None          # Profile type
  foods: list                      # Parsed food items
  profile_config: PatientConfig    # Physiological parameters
  sim_reading: dict                # Current CGM, IOB, trend
  evidence_items: list              # Per-food evidence

  clarification_needed: bool        # Needs user input?
